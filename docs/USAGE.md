# P2P 联机使用说明（Minecraft 26.3 / Fabric / iroh）

`p2plan-iroh` 把原版「对局域网开放」变成**跨网联机**：房主不需要公网服务器、不需要端口映射、
也不需要任何外部联机客户端或加速器。双方装上同一个 mod 就能连。

底层用 [iroh](https://iroh.computer)（QUIC）：自动 NAT 穿透 + 端到端加密 + 公共中继兜底。
你不需要懂这些 —— 下面只有点按钮。

- **房主**：单人存档里按 **Esc** → 「**P2P 开房**」→ 「**开房**」→ 「**复制房间码**」发给朋友。
- **访客**：多人游戏 → 「**粘贴 P2P 房间码加入**」→ 粘贴 → 「**加入**」。

> 房间码里嵌着房主的身份与**邀请口令**：谁拿到这串码就能进房，**别公开发到群里**。
> 房间码默认 **24 小时**有效，过期或房主关房重开后需要重新要一张。

---

## 一、三步开起来

### 第 1 步：房主开房

1. 进入要联机的**单人存档**（主界面开不了房，必须有存档）。
2. 按 **Esc** 打开暂停菜单 → 点底部「**P2P 开房**」进入面板。
3. （可选）改「**开房端口**」。默认 `65535`，会记住你上次用的值。一般不用动。
4. **关键**：如果朋友是**离线账户**，点「**验证模式：正版**」按钮切到「**验证模式：离线**」。
   - 正版模式：只有正版账户能进；
   - 离线模式：离线账户也能进，且玩家名固定成一个稳定 UUID（改名不丢背包，见第四节）。
   - 这个开关也会**记住**：切过一次后，以后进任何存档都自动是上次那个模式。
5. 点「**开房**」。状态区显示 `正在启动 iroh 端点…` → `iroh 端点已就绪（N 个直连地址）`。
6. 点「**复制房间码**」，把 `P2P3-…` 这一长串发给朋友。

### 第 2 步：访客加入

1. 朋友也装同一个 mod（+ Fabric API）。
2. 主界面 →「**多人游戏**」→ 点左上「**粘贴 P2P 房间码加入**」。
3. 在输入框里 **Ctrl+V** 粘贴房间码 → 点「**加入**」。
   - 如果这个房主之前连过，输入框下方会有**历史房间码**列表：**单击**填入、**双击**直接加入、右侧「**×**」删除失效的。
4. 状态区显示 `正在打洞连接房主…` → 成功后自动进图，进服约 2 秒后聊天栏会播报一次连接方式：
   - `[P2P] 连接方式：直连 · 42 ms · [2408:…]:51600` —— 最好，P2P 直连；
   - `[P2P] 连接方式：中继 · 180 ms · …` —— 走了 iroh 公共中继（热点/校园网常见，能用但延迟高）。

### 第 3 步：玩 / 关房

- 联机时别在面板点「关房」；房主退出存档会自动关房。
- 结束：房主按 **Esc** →「**P2P 开房**」→「**关房**」。
- 命令（房主在聊天框输）：`/p2plan status`、`/p2plan who`、`/p2plan code`、`/p2plan stop`。

## 二、面板控件

| 控件 | 作用 |
|---|---|
| **开房** | 发布集成服务器 + 起 iroh 端点 + 生成房间码。重复点**不会**换码（幂等，否则朋友手里的旧码会失效） |
| **关房** | 收回隧道、取消发布、清房间状态 |
| **开房端口** | 集成服务器端口，默认 65535，记住上次值。开着房改端口不立即生效，要先关再开 |
| **验证模式** | 正版 ↔ 离线，记住偏好 |
| **复制房间码** | 复制到剪贴板 |
| **粘贴 P2P 房间码加入**（多人游戏界面） | 进加入面板 |
| **历史房间码**（加入面板） | 最近连过的房，单击/双击/删除 |

## 三、排障

### 1. 朋友「登录失败：无效会话」

房主还开着正版验证，但朋友是离线账户 → 进不来。让房主点「**验证模式**」切到「**离线**」，
朋友重新点加入即可。（这是最常见的卡点，首次开房时面板会自动提示。）

### 2. 一直「正在打洞连接房主…」后超时

- **口令/码过期**：房间码 24 小时过期；房主若关房又重开，会换一张新码 —— 让房主重新复制一张。
- **网络**：热点、校园网、运营商 CGNAT 通常是对称型 NAT，P2P 打洞会失败，此时 iroh 会自动退到
  公共中继（慢但能用）。如果聊天栏显示「中继」说明就是走的这条路。
- 想更快：双方都开 **IPv6**（手机热点一般没有；家宽可联系运营商开通），直连最稳。

### 3. 需要放行什么防火墙吗？

一般**不需要端口映射**（这是用 iroh 而不是自己架服务器的主要原因）。Windows 首次「开房」弹出的
防火墙提示请点**允许**（专用 + 公用网络都勾）。公司/学校网若整体封锁出站 UDP，可能连不上 ——
这与本 mod 无关，换网络即可。

### 4. 房间码无效

`P2P3-` 开头的一长串是 Base32 短码，改动任意一位都会校验失败。**整段复制**（不要手打、不要漏结尾、
不要混进换行）。聊天气泡截断时让对方分段发或发文件。旧版 `P2P2-`/`P2P1-` 开头的码已不兼容。

### 5. 进服被踢「房间口令不正确」

房主重开过房（口令变了）或粘错码。向房主要最新的一张。

## 四、和「更高级联机设置」(mcwifipnp) 共存

两个模组都会改写**离线 UUID 的来源**（都在 `UUIDUtil.createOfflinePlayerUUID` 同一注入点），
但策略不同：

| 模组 | 离线玩家拿到什么 UUID |
|---|---|
| mcwifipnp | 拿玩家名去匹配 Mojang，取**官方 UUID** |
| p2plan（本模组） | 给一个**稳定 UUID**；若该名已有原版离线玩家数据，则沿用原值 |

两边同时改写会让「同一玩家两次启动拿到不同 UUID」→ 背包/成就像是丢了。所以本模组在检测到
mcwifipnp 的「修复 UUID」开启时**自动让位**（日志打一条 WARN），只管联机隧道、不碰 UUID。
想反过来由本模组接管 UUID：启动参数加 `-Dp2plan.uuidfix=force`，并去 mcwifipnp 界面关掉「修复 UUID」。

> 换过 UUID 的老存档，建议先备份 `saves/<世界>/playerdata/`。

## 五、本地文件（都可用 .gitignore 排除，含隐私）

| 路径 | 内容 |
|---|---|
| `config/p2plan/iroh-key.bin` | 本机 iroh 私钥（决定 NodeID，房间码里那串身份）。**别外传** |
| `config/p2plan/iroh-port.txt` | 记上的次实际监听端口 |
| `config/p2plan/port.txt` | 面板「开房端口」记忆值 |
| `config/p2plan/verify-offline.txt` | 验证模式偏好 |
| `config/p2plan/history.txt` | 历史房间码 |
| `config/p2plan/working-addrs.properties` | 每个房主上次连通的直连地址 |
| `config/p2plan/last-secret.txt` | 最近一次房间口令（重连用） |
| `config/p2plan/identity.txt` + `<世界>/p2plan/identities.txt` | 离线玩家名 ↔ 稳定 UUID |
| `p2plan/native/iroh_ffi.dll` | 运行时解出的 iroh 原生库 |
